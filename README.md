# 我的时间记录

一个**单文件、零依赖、纯前端**的时间记录工具：按项目记录每天的时间段，用三种口径管理投入，并把「被打断的时间」单独归到系统项目「事来则应」。手机上打开即用，数据存在本机浏览器，不需要账号、不需要服务器、不引入任何第三方库。

**跨设备同步是可选项**：开启后数据写入你自己的 Supabase 数据库，两台设备用一张配对二维码对齐——扫一次码即可，不用输任何口令，也不用记账号密码。

- **本地使用**：双击 [`index.html`](./index.html)，用 Chrome / Edge / Safari 等现代浏览器打开即可。无需安装、无需构建、无需联网。
- **在线使用**：把 `index.html` 提交到 GitHub 仓库根目录并开启 GitHub Pages，即可通过 Pages 地址或已绑定的自定义域名（如 `https://oktime.cc`）访问。

> 默认只存在本机浏览器：换浏览器、换设备、无痕窗口、清除浏览器数据都会导致数据不可见或丢失。两种应对——开启跨设备同步，在另一台设备扫码配对；或定期用页面底部的「导出记录」备份成 CSV。

## 核心概念：三组项目 + 一个系统项目

新建项目时先选一组，组决定了这个项目的目标口径和卡片样式。

| 分组             | 含义                                          | 可设置                    | 卡片圆形图标                 |
| -------------- | ------------------------------------------- | ---------------------- | ---------------------- |
| **多多益善**       | 希望每天至少投入多久                                  | 每日目标（分钟）               | 环形进度「已投入 / 目标」，达标保持满环  |
| **适可而止**       | 希望每天别超过多久                                   | 每日上限（分钟）               | 环形进度「已用 / 上限」，超额整环变红填满 |
| **如实知见**       | 只记流水，不设任何目标或上限                              | 无，输完名字即创建完成            | 不显示                    |
| **事来则应**（系统项目） | 早期记录被中断、临时事务的时间；**v0.4B 起不再产生新记录**，只保留旧数据可读 | 无，不可删 / 改名 / 设目标 / 设上限 | 不显示                    |

「事来则应」由系统自动创建，固定中性灰 `#9CA3AF`，视觉上放在「如实知见」组的最后一张卡片，但内部不属于任何组；`⋯` 菜单只保留「清空今日记录」。早期版本里它叫「杂事」，现有代码会自动把旧数据识别并规整为「事来则应」，历史记录不丢。

> **v0.3Z 起分组的呈现方式变了**：三组的语义、目标 / 上限、环形圈、CSV 分组列全部照旧，但在「我的项目」里它们不再各自成段，而是收成一行筛选 chip；默认看到的是一条不分组的扁平清单（3 条）。分组仍是复盘信息，不是快速记录的入口。v0.4B 起「事来则应」只剩旧数据兼容，新的中断流程改走「船上」这一条路（见下文「中断与船上」）。

## 功能详解

### 项目与计时

- 项目名最多 10 个字、不可与现有项目重名；颜色从 8 色调色板依次分配。顶部「＋」先弹三选一分组；v0.3Z 起分组头不再渲染，「在组内新建」入口由顶部分组弹窗承担（等价路径，落组不变）。
- 项目顺序有两种模式（标题行「⇅」切换）：默认「按热度」按调用次数降序（v0.3G）；「按顺序」沿用 `sortIndex` 数值越大越靠前、新建项目排同组首位。「事来则应」不参与排序，固定沉底。
- 卡片按钮统一显示「**开始**」，结束后再次开始仍显示「开始」，不再切换成「继续」；计时中的卡片不再放按钮，「中断」「结束」上浮到状态条活动卡。
- **卡片长什么样（v0.3U「清单 · 呼吸」）**：每张卡改两行网格。第一行是 `7px 项目色圆点 + 项目名（16px）+ 细描边「开始」+ 34px 环形圈 + ⋯`，第二行是 `累计 N 次 · 今日合计 HH:MM · 目标 / 上限说明`，用中点分隔；没有数据时第二行自动不占位。原来 4px 的左侧色条换成圆点，实心蓝胶囊换成细描边，视觉重量整体降下来，一屏能多看到一两个项目。计时中的卡片名字转靛蓝、圆点带一圈浅色光环，判定用 `:has(.proj-actions:empty)`，**零 JS**。
- **没设目标 / 上限就不画圈（v0.3Q）**：`goalOrbHTML()` 在 `targetMinutes` / `dailyLimit` 为空时直接返回空字符串，卡片右侧不再留一个空心圆占位；设置后环形圈立刻出现。设置入口没变——`⋯` →「设置每日目标 / 上限」，或新建项目后自动弹出的设置面板。
- **项目可以在三组之间移动**：`⋯` →「移到其它分组」→ 选目标组。移完排在目标组最前并短暂高亮。已有的每日目标 / 上限按**原数值**搬到新分组（目标 ↔ 上限互转，数值不变），移到「如实知见」则清空这两项；历史记录一条不动，但过去日期的完成率与超额会按新分组重新计算。「事来则应」不参与移动。
- **计时可以「在船上做」（v0.3V 起，v0.4B 收口）**：时间是一条河，主任务像一条船。**船上那件事只能由「中断」产生**：点状态条「中断」→ 在面板里选一件事或新建 →「在船上开始」，新段带可选 `parent` 指向船段，**船继续走、不自动结束**。状态条给它单独一行 `● 项目名 · 船上 00:xx [收]`；船卡片第三行是 `⤷ 船上 · 项目名` 加 `合计 xx:xx · 净 xx:xx`（净 = 合计 − 船上合计，不会为负；**合计本身照原样显示，不做减法替换**）。同一条船上一次只做一件事，再开一件会直接顶掉旧的（静默结束，v0.4B 起不再弹「已记录」提示）；点船的「结束 / 中断」会连带结束船上那件事，点船上的「收」只结束这一件、船照走。**v0.4B 起恢复互斥**：船在走时直接点别的项目「开始」不再挂上船，而是结束当前船（连船上那件一起）并开一条新船，弹「《船》已记录 N 分钟」。旧链路里的「事来则应」项目与自动代记仍可读可算，但新面板不再调用它。
- 计时中的状态条每秒只更新「已计时」数字，不会整页重绘，因此不会打断菜单、弹层或输入焦点。
- **分类作筛选、清单默认 3 条（v0.3Z）**：搜索框下是一行 4 个 chip——「全部 N」「多多益善 N」「适可而止 N」「如实知见 N」，默认「全部」。点某组只显示该组项目，并在下方补一行该组当日汇总；「事来则应」计入「如实知见」，各 chip 之和 = 全部。清单是**一条扁平列表**（不再按组分段），默认只画 3 张卡，其余收进「⋯ 还有 N 项 · 展开全部」，展开后按钮变「⋯ 收起」。换分类会回到 3 条、不带上一组的展开态。原分组渲染函数 `block()` 整段保留，只是不再作为默认视图；目标 / 上限、CSV 分组列与统计口径仍按 `group` 字段照旧工作。
- **v0.3E 的「每组 3 项」折叠**在 v0.3Z 后被扁平清单取代；`GROUP_VISIBLE_COUNT` / `expandedGroups` 保留但默认视图不再走它。
- **进行中的项目强制可见**：即使它排在 3 条之外，也会被提到可见区（相对顺序不变、「还有 N 项」计数相应扣减），否则会连「中断 / 结束」都点不到。新建 / 移动后的高亮项目（`revealPid`）同样强制可见。「按顺序」模式下新建项目（`nextSortIndex()` 排最前）与「移到其它分组」后排到新组首位的项目会自动进入前 3 项；「按热度」模式下这两类项目是 0 次，靠高亮期间的强制可见露出（见下）。
- 折叠与分类筛选都是**纯 UI 状态**：`expandedGroups`、`catFilter`、`flatListOpen` 只存在内存里，不写 `state`、不进 localStorage、不参与同步，刷新后回到「全部 + 收起 3 条」；统计、时间分布、小时明细与历史记录都按完整项目列表计算，切换前后完全一致。
- **项目搜索（v0.3F）**：「我的项目」标题下方常驻一个搜索框（放大镜 + 输入框 + 清除 ×）。输入即按**项目名**过滤：忽略大小写、支持中文子串、空格分隔多个词需全部命中、自动忽略首尾空格；`Esc` 或 × 清空。项目只有 `name` 一个文本字段（≤10 字），没有备注 / 标签，也没有拼音或首字母搜索。
- **搜索结果跨组平铺**：有关键词时忽略分类筛选与清单折叠，把所有匹配项按当前显示顺序（默认按热度、切回后按 `sortIndex`）列成一组，顶部显示「找到 N 项」，最多渲染 20 条并提示补充关键词；chip 在搜索时隐藏。结果复用完整项目卡，**直接点「开始」即可计时**，右侧 `⋯` 菜单、目标环、今日合计都在。
- **点开始就退出搜索（v0.3Y）**：搜索结果里点「开始」后输入框静默清空、`has-value` 移除、× 隐藏、「找到 N 项」消失，回到默认视图。用的是 `clearSearchQuietly()`，**不抢焦点**（手机上不会弹键盘），也不写 `state` / 不触发同步。手点 × 或按 `Esc` 仍走 `clearSearch()` 并聚焦输入框，可以接着搜下一个。
- 清空关键词立刻回到「分类筛选 + 3 条清单」视图，此前选过的分类与展开态原样保留（`catFilter` / `flatListOpen` 不受影响）。没有匹配时给「没有找到「…」」提示，关键词经 `esc()` 转义，不会注入 HTML。
- 搜索是**纯 UI 状态**：`searchQuery` 只存内存，不写 `state`、不进 localStorage、不参与同步，刷新即清空；过滤只局部重绘项目列表，不触发 `save()` / 同步钩子。统计、时间分布、小时明细与历史记录始终按完整项目列表计算，搜索前后完全一致。
- **按调用次数排序（v0.3G）**：默认「⇅ 按热度」，三组内各自按调用次数降序；次数相同回退 `sortIndex` 降序（新建 / 移动后的 0 次项目仍是「0 次区」第一，不会沉到末尾），再相同回退原始下标保证稳定。系统项目「事来则应」不参与排序、始终沉底，也不显示次数。因而折叠露出的前 3 项就是该组调用最多的 3 项。
- **次数口径：从记录段现算，不存计数器**。`useCountMap()` 遍历 `state.days` 所有天，统计每个项目名下的时间段条数（含今天、含补记与中断代记；跨零点拆段会算两次，属可接受的罕见情况）。好处是上线即刻按历史记录排出热度、老数据零迁移、删记录次数自动减；更关键的是同步合并按段 `id` 去重、两端独有的段都保留，所以次数天然是两端之和，不会出现两台手机各自点了几次、同步后少算的情况。
- 标题行「⇅ 按热度」/「⇅ 按顺序」显示当前模式，点击切换；偏好存独立 localStorage 键 `my-time-records:sort-mode:v1`，不进 `state`、不参与同步、刷新保留，各设备可有自己的偏好。两种模式下卡片右侧都显示「累计 N 次」淡灰小字（放在 `.proj-today` 列内，不占水平宽度，避免窄屏挤压项目名）。
- **新建 / 移动后仍看得见**：高亮期间的项目（`revealPid`）与进行中项目一样强制放进折叠可见区，否则热度排序下 0 次项目会沉进「还有 N 项」、`applyReveal()` 找不到卡片，浅蓝高亮与自动滚动都会失效。新建后紧接的「设置目标」面板会盖住高亮（1.3 秒即过期），关掉面板时重新高亮一次；若新建时还停在搜索视图，会先静默清空搜索词再高亮。

### 中断与船上（v0.4B 起单弹窗）

点计时中状态条上的「中断」，只会弹出**一个**面板，标题是 `中断《当前项目》· 选一件船上的事`：

- **搜索框**：`搜已建项目，或输入新事项名`。输入即过滤，最近用过的排前面；面板顶部先列「最近用过」3 项，再列「全部项目」。
- **找不到就新建**：搜不到时结果区直接变「没有找到「X」· 就在这里新建」，展开名字（≤10 字）+ 归到哪一类（多多益善 / 适可而止 / **如实知见默认**）。建好即选中并常驻「我的项目」，不是一次性的临时项。
- **两个按钮**：「**在船上开始 · 项目名**」（实心，未选时禁用）与「**结束**」（描边）。想收工就点「结束」，等效于状态条上的「结束」。
- **点面板外不算结束**：点遮罩、按 `Escape`、下滑关闭，都只关闭弹窗——不中断、不结束、不写任何 `state`。
- 「在船上开始」会把当前段留在原处继续跑，新段带 `parent` 指向它；同一条船再开一件会直接顶掉旧的，不弹提示。

> **没有「只中断」了（v0.4B）**。四种原因 chip（喝咖啡 / 接电话 / 临时被叫走 / 事来则应）与「只中断」按钮整个移除：中断必须落到一件具体的事上，否则就点「结束」。旧的 `doInterrupt()` / `startChoreSegment()` 与系统项目「事来则应」只作为历史数据的读取与兼容链路保留，新界面不再产生新的「事来则应」段。

### 编辑、删除与补记

| 操作     | 入口                                          | 说明                                                                                                                                     |
| ------ | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 编辑一段时间 | 今日概览小时明细行、历史记录行右侧 `✎`（v0.3L 起；v0.3W 起历史行也有） | 两个 `type=time` 输入 + 备注（带最近三条候选）+ **可改所属项目**（v0.4D 恢复）+ 实时时长预览；标题下是项目胶囊 `● 工作 ▾`，右端一行小字「只改归属」，点开底部面板选另一个项目，选中只是登记、点「保存」才换桶；进行中的段需先结束再编辑 |
| 删除一段时间 | 今日概览小时明细行、历史记录行右侧 `×`（v0.3W 起历史行也有）         | 弹确认框「撤销这段记录」，删除后不可恢复；所有合计、百分比、时间轴同步扣除。确认文案按日期区分：今天写「今日总时长」，过去写「当天总时长」                                                                  |
| 补记一段时间 | 时间分布明细框「＋ 补记一段时间」/ 历史记录「＋ 记一段」              | 可搜索项目选择器：默认空白不预选，输入项目名即过滤，候选按三组 + 系统分组、最多 20 条，点一行即选中；默认时间段取该小时最长空白段（历史记录取当天最长空白段）并限制不晚于现在；保存为已完成段（v0.3K）                              |

**补记弹窗内直接新建项目**：弹窗底部有「＋ 直接新建项目」，展开一块内联表单（项目名 + 分组 + 目标/上限），不必退出弹窗去顶部新建再回来。展开时选择器被禁用，避免「既选了项目又填了新名」的歧义；建项目发生在所有校验（时间、项目名）通过之后，因此校验失败不会留下空项目。

**编辑弹窗可以改所属项目（v0.4D 恢复，v0.3X 曾整块删除）**：v0.3J / v0.3K 加的项目选择器在 v0.3X 被当成「很少用到」整块删掉，v0.4D 把它以更轻的形态接回来——标题下只留一枚项目胶囊 `● 工作 ▾`，点开是底部面板「这段记录改到哪个项目」（副标题固定显示 `工作 · 09:10 – 10:05`，防止忘了在改哪一段）。面板里可搜索，当前项标「当前」，其余标分组名；**搜不到时整块变空态，直接给「＋ 新建「PPT 复盘」」，关键词自动带进名字、默认「如实知见」**。选中只改胶囊显示（`工作 → 阅读 · 保存后生效`），**点「保存」才真正换桶**；点取消什么都不动，连刚新建的项目一起撤掉。换桶仍只挪同一个 `seg` 对象，`id` / 起止 / `note` / `endType` / 日期全不变；系统「事来则应」的记录胶囊锁定，提示「系统项目 · 归属固定」。同时弹窗整体重排：时间标签轻、数值重，备注标签右侧写「可选 · 最多 50 字」，时长改浅蓝汇总条，报错在原地显示，空错误不占高。

**历史记录也能编辑 / 删除（v0.3W）**：历史记录不再是只读视图，每行与今日小时明细同款，带 `✎ 编辑` / `× 删除`（进行中的段只给 `×`）。按钮带 `data-day`，`openEditRecordModal` / `openDeleteRecordModal` / `saveRecordEdit` / `deleteRecordById` 都接受可选的 `dayKey`，不传时默认今天；弹层副标题**不标日期**；删除确认按日期区分「今日总时长」/「当天总时长」。改哪天就落在哪天的桶里，今天与统计口径互不干扰。

**弹窗内项目选择改为搜索（v0.3K）**：补记与编辑两个弹窗的「事项（项目）」由原生 `<select>` 换成**可搜索选择器**——搜索框 +「已选」条 + 限高候选列表；输入项目名即过滤（复用主界面同款口径：空格分词 AND、忽略大小写、最多 20 条），点一行即选中，组别以小标签显示而不再用 `optgroup` 大标题。补记弹窗**默认空白不预选**，未选时保存会提示「请选择要补记的项目」；编辑弹窗仍预选当前段归属且排除系统项目。选中 pid 仍存 `#add-project`（改为 hidden 字段），两个保存函数、超额提示与内联新建链路零改动；搜索词只存在于弹窗 DOM，关闭即消失，不写 `state` / localStorage、不触发 `save()` / 同步。搜索框按 Enter 只选中第一个候选，不会误触保存。（v0.3X 起编辑弹窗不再使用项目选择器，本节描述现在只适用于补记弹窗。）

**备注框可以直接点最近三条（v0.3S）**：补记、编辑、以及 v0.4C 起的「调整开始时间」三个弹窗，备注框下方都会多出「最近用过 · 项目名」和最多 3 枚浅蓝胶囊。点一下就把那句备注填进输入框、光标落在句尾，**仍然可以继续改、清空或整句重打**；手动打字后高亮消失。候选完全从已有记录里现算（`recentNotesForProject()` 只读 `state.days`），**不新增存储字段、不改数据结构、不写新的 localStorage 键**，所以别的设备同步过来的备注也会自然出现在候选里。取数口径：按当前项目、同句去重、排除正在编辑的这一段、排除系统自动生成的「因《X》中断」、按记录段的开始时间倒序；一句都没写过就整块不显示（不留空标签）。换项目时候选立刻刷新；补记弹窗默认不预选项目，所以**先选事项才出现候选**，编辑弹窗打开即可见。

**计时中可以直接改开始时间（v0.3O）**：点状态条上的已计时数字，弹出「调整开始时间」——显示当前起点与已计时，可以改钟点，也可以按 `−15 分钟 / −30 分钟 / −1 小时` 快捷回拨，改的时候下面实时预览新的起点与已计时。保存**只改 `start` 一个字段**，`id`、所属项目、备注、`endType=running`、`end=null` 全都不动，所以计时不会被中断、也不会多出一段。校验三条：必须在今天 0 点之后、早于现在、不跨天；调过的段会带一个「起点已调整」小标记。跨设备同步也做了兼容：新段在开始时写入 `originStart`（最初点「开始」的时刻），旧段第一次被调整时补写，合并时靠它认出「两端说的是同一段」。**v0.4C 起这个弹窗同时承担备注**：弹窗下半部分多一个「备注（最多 50 字，可留空）」输入框与「最近用过」胶囊，与改时间互不影响。保存分四路——只改备注（写 `seg.note`，时间不动，提示「备注已记下」）、只改时间（起点变、备注原样，提示「起点已调为 HH:MM」）、两样都改（提示拼接）、两样都没动（直接关闭，不写入、不提示）。时间输入精度只到分钟，所以判定加了 **60 秒容差**：与当前起点落在同一分钟即视为「没改时间」，否则「只补备注」会被误判成调整起点、还会把起点里原本的秒数抹掉。小屏内容超过一屏时，按钮行吸在面板底部（带分隔线与浅阴影），不用滚也能看见「保存」。

编辑与补记写入后，概览里的小时明细、时间轴色块、CSV、记录卡、历史记录全部从同一份状态实时重算，不需要任何手动同步。备注直接跟在「N 分钟」后面显示：今日小时明细一行空间窄，超长由 CSS 省略（`.tl-note` 限宽 38%），不再折叠成「点开看全文」（v0.3L 起）；历史记录一行更宽，备注完整换行显示。

### 历史记录

用来回看和补填过去某一天。

- 日期默认是**北京时间的今天**；`‹` `›` 前后翻一天，`›` 在今天时禁用，日期选择器不能选未来。
- 标题显示 `YYYY-MM-DD 星期X`，右侧一行小字「共 N 段 · **覆盖** H:MM」；当天各段有重叠时，再补一句小字「累计投入 Y（含 Z 重叠）」。覆盖是把当天所有区间夹到 0 点–24 点后求并集，**恒不超过 24 小时**；累计投入仍是各段直接相加（v0.4A）。
- 当天有记录时按**从早到晚**列出每段的项目、起止钟点、标签（计时中 / 中断）、备注与来源项目。
- **默认只显示前 5 条（v0.3I）**：与概览的小时明细共用同一套记录行样式与分页口径，段数超过 5 条时底部出现「展开全部（共 N 条）」，点开看全天、按钮变「收起」；≤ 5 段或空日期不出现按钮。默认露出当天最早的 5 段，展开后仍是从早到晚。切换日期（前后翻 / 日期选择器）会自动收回；展开状态只存内存、刷新即复位。
- **可逐条编辑 / 删除（v0.3W）**：历史行不再是只读，与今日小时明细同款带 `✎ 编辑` / `× 删除`；改钟点与备注、删段都直接作用于当前查看的那一天（按钮带 `data-day`），弹层不标日期，删除确认写「当天总时长」。进行中的段只给 `×`，仍须先结束才能编辑。
- **船上那件事折叠在主段下面（v0.4B）**：主段若带船上记录，时长显示为「合计 X · 净 Y」，下面缩进一行 `⤷ 项目名 [船上] 09:20–09:45 25 分`，同样带 `✎` / `×`，可以单独改、单独删；主段删掉时它的船上子行一起消失（同属这一天同一棵树）。
- 当天没有记录时显示「暂无记录」，并提示可点右上「＋ 记一段」补填，或换一个日期。
- 该模块的「＋ 记一段」打开的就是首页那个补记弹窗，只是目标日期取当前选中的那一天：**补到哪天就记在哪天，不计入今天**。
- 日期判断一律按北京时间（`bjDayKeyOf` / `bjTodayKey`），不随设备时区漂移；旧记录保留原本的日期与数量，不做任何重算。


### 今日时间分布（v0.3M 方案 B，v0.3T 起无独立标题）

24 格仍然是 1 小时一格、可点，视觉层在 v0.3M 做了精简：**一格一色**，不再往格子里叠多段比例色块和空白斜纹。v0.3T 起这一块**不再有自己的标题**——「今日概览」标题行右侧只有一行小字「每格1小时·点开看明细」，点开某格后它变成「再点一次收起」。

- **概览卡只剩这一块（v0.3T）**：今日累计大数字、目标、完成百分比、细进度条与「适可而止」超额汇总整块已删，卡片高度从约 383px 压到约 167px，首屏能多露 1–2 个项目。
- **一格一色**：取这一小时里**占时最长**那一段的项目色。重叠的段先按区间合并去重，再算覆盖率，不会重复累加——这与 v0.4A 的「覆盖」是同一套区间并集思路，所以 24 格从来不会因为重叠而变长。
- **深浅 = 这一小时的投入**：按该小时记录区间的并集长度 / 60 换算成 `opacity` 0.28–1，满一小时为 1。没记录的格子保持底色 `#EDF1F7`，不填色。
- **无边框细格**：24 格是无缝排列的圆角细格（3px 间隙、5px 圆角、28px 高），颜色本身就是分隔，不再画边框。
- **刻度在色带下方**：`0 / 6 / 12 / 18 / 23` 移到格子下方并降一档灰度，让色带本身更安静。
- **图例压成一行**：`■ 有记录　□ 空白　深浅 = 这一小时的投入`，不再逐项列出十几种项目色。项目名与颜色在点开的明细里逐行给出，信息没有丢。
- **点格子展开该小时明细**：上方是记录段（项目名、真实起止、整段分钟、计时中 / 中断标签、来源项目、备注），下方是落在这一小时里的空白区间；再点一次收起。明细里可用 `✎` 编辑、`×` 删除，底部「＋ 补记一段时间」直接补记这一小时。计时中的段只给 `×`（要先结束才能编辑）。
- **跨小时的段**会在它横跨的两个格子里各出现一次，但两处都指向**同一段**（显示的是真实起止与整段分钟，与编辑弹窗一致），不是被拆成了两段。
- **单小时互斥**：同时只展开一个小时，点另一个会自动收起前一个。`timelineHour` 只是内存里的 UI 状态，不写 `state`、不进 localStorage、不参与同步，刷新即回到全部收起。
- **空白小字**采用**活动区间口径**：区间 = 今天第一条记录起点 → 最后一条记录终点，区间外的时段不计入；显示「活动区间 HH:MM–HH:MM · 空白 X · 最长 HH:MM–HH:MM」，没有空白时显示「没有空白」。

### 每日上限、超额与统计口径

- 「适可而止」项目超过每日上限时，只做提示**不自动结束计时、也不禁止开始**：刚超额时顶部弹一次橙色提示条，项目卡上常驻「已超 N 分钟」小字。v0.3T 起概览里那个「适可而止：N 个项目，M 个超额」的汇总入口已随整块删除，超额信息改由项目卡与提示条承担。
- 「今日合计」= 当天所有项目所有段之和，**包含「事来则应」和未设目标的项目**；这是「累计投入」口径，同一段时间被两条记录覆盖时会重复计入，所以它可能超过 24 小时。**v0.4A 起另有「覆盖」口径**：`computeCoveredMinutes()` 把所有区间夹到当天 0 点–次日 0 点后求并集，结果恒 ≤1440 分钟，用于历史标题、记录卡与 CSV 的按日汇总。两个数字并存，不做替换。
- 「完成 X%」只&#x6309;**「多多益善」组里设置了每日目标**的项目计算：分子是这些项目今天已投入之和，分母是它们的目标之和。「适可而止」「如实知见」「事来则应」与未设目标的项目都不参与。超过 100% 照实显示。**这个口径仍然存在**（CSV 的按日汇总里有「多多益善完成率」，记录卡也画完成百分比与进度条），只是 v0.3T 起概览卡不再显示全局的完成度大数字与进度条；单个项目的完成情况看它卡片上的环形圈。
- 「其中船上 XX 分钟」仅在有船上记录时显示（v0.4B 起取代原来的「其中事来则应」），位置在「生成今日记录卡」的图里（v0.3T 起概览卡不再显示这行小字）。
- **为什么原来会算出 31 小时 59 分**：旧版把各段直接相加，且查看历史日期时未结束的段仍拿「现在」当终点，于是一段前天开始、一直没结束的记录会被算成跨到今天的三十多个小时；船上穿插与「中断后代记」又让同一段时间被两条记录覆盖，相加自然超过 24 小时。v0.4A 的做法是「显示两个数」而不是「改掉原数」：覆盖回答「这一天被占了多少」，累计投入回答「一共投进去多少」。
- 跨天时会把进行中的段按午夜切分归属到各天；30 秒轮询只检测是否跨天，不改动任何数字。

### 生成今日记录卡 / 导出记录

- **生成今日记录卡**：弹窗预览一张 Canvas 绘制的 PNG（750px 宽、2 倍位图，高度随项目数增长），包含昵称、日期与星期、**今日覆盖**（v0.4A 起，不再是各段相加）、目标完成百分比、进度条、「其中船上 XX 分钟」（v0.4B 起），以及按三组分段列出的今日各项目小计。点「保存图片」下载为 `我的时间记录-YYYY-MM-DD.png`，移动端可长按图片保存到相册。
- **导出记录**：把**全部历史**（不止今天）导出为带 UTF-8 BOM 的 CSV（防中文乱码），文件名为 `我的时间记录-YYYY-MM-DD.csv`。明细共 **19 列**：

  `日期 / 项目 / 分组 / 开始 / 结束 / 时长(分钟) / 状态 / 备注 / 来源项目 / 每日目标_分钟 / 每日上限_分钟 / 当日已用_分钟 / 是否超额 / 超额_分钟 / 按日汇总_今日合计_分钟 / 按日汇总_目标合计_分钟 / 按日汇总_完成率 / 按日汇总_记录段数 / 按日汇总_超额项目数`

  明细之后空一行，再追加**按日汇总区**：`日期 / 今日合计_分钟 / 覆盖_分钟 / 目标合计_分钟 / 完成率 / 记录段数 / 超额项目数 / 多多益善完成率`（`覆盖_分钟` 为 v0.4A 新增，紧跟今日合计）。明细区的 19 列与「时长(分钟)」口径没有变，仍是各段自身的长度。状态为「计时中 / 中断 / 完成」，进行中的段结束时间写「进行中」。导出只读数据，不改动任何记录与统计；无记录时提示「暂无记录可导出」。

### 跨设备同步与配对（可选）

默认关闭。开启后两台设备看到同一份记录，数据在你自己的 Supabase 库里；关掉同步不影响本地记录。

启用后同步条是**并排两块**：左边「已同步 · N 分钟前 ›」点开同步设置，右边「⟳ 立即同步」（v0.3H）点一下立刻从云端拉取最新记录，**不用刷新网页**。未启用时只有左边一条，不显示按钮。

**第一次开启**：点页面底部「跨设备同步 · 未启用」→「随机生成一个」（自动填 `ok-xxxxxx-xxxx`，14 位，去掉易混字符）→「启用并同步」。同步成功后**配对二维码自动弹出**，不用再点第二次。

**给第二台设备配对**：直接扫那个码；或在已启用的设备上点同步条 →「配对一台新设备」→ 复制链接发过去。链接形如 `https://oktime.cc/?pair=<同步码>`。

- 打开带 `?pair=` 的链接会自动填码、启用并同步，随后**立刻把参数从地址栏抹掉**（不留在浏览历史里，也不随外链 Referer 带出去）。
- 本机已有记录时按合并处理，云端不会覆盖本机；本机为空则直接采用云端。
- 已配对的设备再扫同一个码只提示「这台设备已经配对了」，不会把版本号重置为 0。
- 同步码至少 12 位，两台必须一字不差；**码等于钥匙**，谁拿到链接谁就能读到你的记录，只发给你自己的设备。
- 同步不是实时推送：本机改动后节流 2.5 秒上行；**本机没改动时页面开着不会主动去云端取**。想立刻看到另一台设备的更新，点「⟳ 立即同步」或刷新网页。断网时本地照常记录，恢复后自动补传。
- **切回前台会自动补拉一次（v0.3N）**：当本机正有计时中的段、且没有弹窗打开时，从后台切回页面会自动 pull 一次。这是为了修「手机在计时、电脑端看着像没在计时」的观感问题——只在有进行中段时触发，不会变成轮询。
- 冲突按 `rev` 乐观锁处理：版本被别的设备抢先推进时，重新拉取、按记录 id 合并后重推一次；仍失败则提示「两台设备同时在改，请稍后再试」。删除也能同步——云端变了而本地没改动时整体采用云端。
- **同一段不会被拆成两条（v0.3N）**：合并时对「同一个 `id` 且起点相同」的段认作同一段（`mergeSameSegment()`），合并规则是「已结束优先、结束更晚优先、备注与来源取非空」。修之前，一段在两端各自结束、`end` 不同，会被当成撞号而生成一条 `_m` 副本，于是出现「计时还在进行却多出一条」；修之后只在真的同 id 同起点时才合并。调整过起点的段靠 `originStart` 也认得出是同一段（v0.3O）。已知取舍：段上没有 `updatedAt`，两端都调整过起点时取更早的那个起点。

> 扫码用的那个浏览器，就是以后记记录的那个浏览器（微信扫码会落在微信的存储里，和 Safari 不共享）。建议扫码后「添加到主屏幕」，固定在同一个入口打开。

## 数据与存储

数据以单个 JSON 对象存于 `localStorage["my-time-records:v1"]`。`localStorage` 不可用时自动降级为内存态（当次会话仍可用，关闭即丢失）。

```js
{
  schemaVersion: 1,
  nickname: "时间记录员",
  nextColorIndex: 7,           // 下一个项目使用的调色板下标
  nextId: 100,                 // 自增 id 计数器
  currentDayKey: "2026-11-08",
  projects: [
    {
      id: "p_read", name: "阅读", colorIndex: 0,
      targetMinutes: 120,      // 每日目标（分钟），null 表示未设置
      dailyLimit: null,        // 每日上限（分钟），null 表示未设置
      createdAt: 1736899200000,
      sortIndex: 700,          // 越大越靠前
      group: "more"            // more / less / flow
    },
    {
      id: "sys_chore", name: "事来则应", colorIndex: 0,
      targetMinutes: null, dailyLimit: null, createdAt: 1736899200000,
      sortIndex: 0, isSystem: true, group: null   // 系统项目，固定沉底
    }
  ],
  days: {
    "2026-11-08": {
      "p_read": [
        {
          id: "s_2",
          start: 1736902800000,
          originStart: 1736902800000, // 最初点「开始」的时刻，调整起点后不变（可选）
          end: 1736904600000,
          endType: "finished",  // running / interrupted / finished
          note: "",             // 备注，最长 50 字
          sourceProject: ""     // 承接来源项目名，最长 10 字
          // parent: "s_1"      // 仅「船上」的段才有，指向船段 id（可选）
        }
      ]
    }
  }
}
```

| 字段                             | 说明                                                                        |
| ------------------------------ | ------------------------------------------------------------------------- |
| `endType`                      | `running`（进行中，`end` 为 `null`）/ `interrupted`（中断闭合）/ `finished`（正常结束或系统代关） |
| `group`                        | `more` / `less` / `flow`；系统「事来则应」为 `null`。旧数据缺字段一律归 `more`                |
| `targetMinutes` / `dailyLimit` | 分钟数或 `null`；两个字段独立，分别服务「多多益善」与「适可而止」                                      |
| `parent`                       | 可选。只有「船上」的段才有，值是船段 `id`；旧段没有这个键即走原逻辑，`sanitizeSegment()` 不补写              |
| `originStart`                  | 可选。最初点「开始」的时刻，只有调整过起点或跨端合并需要认身份时才写入；与 `start` 不同即说明起点被调过                  |
| `isSystem`                     | 系统项目标记，不可删除 / 改名 / 设目标 / 设上限                                              |
| `days`                         | 以 `YYYY-MM-DD` 为键，值为 `项目id -> 时间段数组`                                      |

**覆盖 / 净时长都是派生值，不落库**：`coveredMinutes` / `rawTotalMinutes` / `boatMinutes` 都在 `computeDayStats()` 里现算，`totalMinutes` 仍是各段相加的原值。所以导出、同步包与 `state` 结构不受影响，回滚到旧版也不会读不懂。

**旧数据兼容**：读取时统一做轻量校验与迁移——字段缺失补默认值、非法值丢弃，`sanitizeSegment()` 对老记录缺失的 `note` / `sourceProject` 按空值处理；`ensureSortIndexes()` 为缺 `sortIndex` 的项目补值；`ensureChoreProject()` 补齐并规整系统项目。早期版本里名为「杂事」、甚至没有 `isSystem` 标记的系统项目，仍会通过 `CHORE_NAME_LEGACY` 被识别，原地改名为「事来则应」并合并记录，**不丢数据**。`schemaVersion` 目前仅支持 1。

### 同步的存储（可选）

不开同步时，只有上面这一个 localStorage 键。开启后多出两处：

| 位置                                        | 内容                                                                               |
| ----------------------------------------- | -------------------------------------------------------------------------------- |
| `localStorage["my-time-records:sync:v1"]` | 同步码明文、`lastRev`（上次看到的云端版本号）、`lastAt`（上次同步时间）、`enabled`。只存在这台设备上                  |
| Supabase Postgres 表 `public.ttr_sync`     | `code_hash`（同步码的 sha256，主键）/ `payload`（整份状态的 jsonb 快照）/ `rev`（版本号）/ `updated_at` |

云端每个同步码对应表里**一行**，存整份快照而不是增量日志，每次推送 `rev + 1`。表上没有开放任何直连策略（`revoke all on table`），只把两个 `security definer` 函数授权给匿名角色：

- `ttr_pull(p_code)` —— 按码哈希取回快照
- `ttr_push(p_code, p_payload, p_base_rev)` —— 乐观锁写入，`rev` 不等于 `p_base_rev` 时拒绝

因此 publishable key 写在页面里是设计允许的：拿到它也只能调这两个函数，不知道码就取不到任何一行数据（直接查表返回 401）。

> 想了解整体流程与取舍，见下方「同步原理说明书（大白话版）」。

## 同步原理说明书（大白话版）

> 这一节只讲「它到底是怎么跑起来的」，不需要你做任何操作。怎么开启和扫码见上文「跨设备同步与配对」，数据格式见「数据与存储」。以下描述对应当前代码 `v0.4D`。

### 一、为什么是「路线二」

`oktime.cc` 托管在 GitHub Pages 上，那里**只能放静态网页**：没有数据库、跑不了后端程序。当初摆着三条路：

| 路线            | 做法                                               | 结论                                                                                                 |
| ------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 路线 1          | 整站迁到带云函数的托管平台，同域调用                               | 可行，但要搬家、要改部署                                                                                       |
| 路线 3          | 用 iframe 把平台页面嵌进 `oktime.cc`                     | **实测不可行**：对方响应头的 CSP `frame-ancestors` 白名单不含 `oktime.cc`，浏览器直接拦截；浏览器判定的是 URL 的 origin，改 CNAME 也绕不过 |
| **路线 2（选中的）** | **GitHub Pages 不动，另接一个外部后端，CORS 放行 `oktime.cc`** | 网页零改动，加个云端仓库即可                                                                                     |

具体落地成三件事：

- 网页还是那个纯静态单文件，零框架、零 CDN、零构建、零第三方库；
- 数据放在**你自己的 Supabase 项目**（Postgres）里；
- 浏览器用原生 `fetch` 跨域调 Supabase 的 REST 接口。跨域这一关由 Supabase 默认放行的 CORS 解决，所以 `oktime.cc` 的静态页可以直接调，不需要自己写服务端、也不需要引 `supabase-js`。

一句话：**网页没变，只是给它配了个云端小仓库。**

### 二、打个比方：小区门口的储物柜

| 角色        | 对应什么                                          | 要点                                                          |
| --------- | --------------------------------------------- | ----------------------------------------------------------- |
| 各自家里的笔记本  | 每台设备浏览器的 `localStorage["my-time-records:v1"]` | **永远是主本**。断网、云端挂了、同步失败，照常记录、照常存本机                           |
| 一个带编号的储物柜 | 云端 `public.ttr_sync` 表里的**一行**                | 柜子里只放一包东西：整份状态打包成的 JSON 快照，外加版本号 `rev` 和更新时间。不是一条条增量日志      |
| 柜子钥匙      | 同步码（至少 12 位，如 `ok-7f3k2m9q-x8v4`）             | A 设备设一个码 = 开了 1 号柜；B 设备填同一个码 / 扫同一个二维码 = 拿同一把钥匙，两台从此读写同一个柜子 |

云端每个同步码对应一行，每次推送 `rev + 1`。整包快照意味着：**云端只有「最新一版」这个概念，没有历史版本**。

### 三、钥匙为什么不容易被偷看

| 三道门              | 大白话                                                                                                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **库里只存指纹**       | 表里 `code_hash` 存的是同步码的 sha256，不存明文。就算有人把整张表拖走，也倒推不出你的同步码。哈希是在云端 SQL 函数里现算的，码只通过 HTTPS 传过去                                                                                                    |
| **表被锁死，只开两个窗口**  | 表开了 RLS 且 `revoke all`，页面里那串 `sb_publishable_...` 本来就是公开钥匙、不是秘密（写在静态 HTML 里谁都看得到）。真正的门锁是：拿着它**一行数据都直查不到**，只能喊两个「办事员」——`ttr_pull`（取）和 `ttr_push`（存）。当初专门验过：用 publishable key 直接 dump 整表返回 401 |
| **二维码 = 把码塞进链接** | A 设备生成的二维码内容就是 `https://oktime.cc/?pair=<同步码>`。B 扫码打开网页后，页面自动把码存进本机配置、**立刻把地址栏的 `?pair=` 抹掉**（不进历史、不随 Referer 外带），然后开始同步。所以你一个字都不用输                                                          |

> 代价也很直白：**同步码 / 配对链接等同于密码**，谁拿到谁就能读你的记录。只发给你自己的设备。

### 四、一次同步怎么跑

所有业务写入都经过唯一的 `save()`，同步钩子就挂在这一处（所以新增任何功能都自动具备同步能力，不用逐个补）：

```text
任何一处改动 → save() 写本机 → 打「脏」标记 → 2.5 秒节流（连点几次只传一次）
                                              │
                         先 pull：云端现在是第几版？那包是什么？
                                              │
   ┌────────────────┬────────────────┬────────────────┬──────────────────┐
   │ 版本没变       │ 云端新了       │ 本地改了       │ 两端都改了       │
   │ 本地也没改     │ 本地没改       │ 云端没变       │                  │
   │ → 什么都不做   │ → 整包搬回本机 │ → 整包推上去   │ → 先合并再推     │
   └────────────────┴────────────────┴────────────────┴──────────────────┘
                                              │
                  push 时声明「我是基于第 N 版（p_base_rev）改的」
                        云端 rev == N → 接受，rev + 1，本机记下新 rev
                        云端 rev != N → 返回 conflict → 重新拉、合并、再推一次
```

「云端新了、本地没改就整包采用云端」这一条很关键：**删除操作因此能跨设备生效**，不会因为在另一台删了、这台又推旧包而被复活。

**触发时机**：打开页面 0.7 秒后无条件拉一次；本机改动节流 2.5 秒后上行；切回前台、网络恢复、每 15 秒兜底**只在本机有未同步改动或上次失败时**才触发（纯接收端不会因此拉到新数据）。此外「⟳ 立即同步」按钮（v0.3H）可随时手动拉一次。失败只会在同步条上标一句「上次失败」，本地数据一行不丢。

### 五、乐观锁与合并（两台手机同时记怎么办）

`rev` 就是那句「基于第几版」的凭据，叫**乐观锁**：不加锁、不排队，谁先推谁成功；后推的那个因为版本号对不上被拒收，于是**重新拉最新版 → 合并自己的改动 → 再推一次**。这样慢一点的那台也不会把对方刚记的盖掉。只有重试还撞上（极端同时写）才提示「两台设备同时在改，请稍后再试」。

合并的口径不是「逐字段挑谁更新谁赢」，而是**以云端那包为基底，把本地独有的东西补进去**：

- 项目和记录都按 `id` 去重，本地多出来的项目 / 时间段追加进去；
- 两台各自新建却撞了同一个 `id` 时，给本地这个换个新 `id`（`_m`、`_m2`…）**两条都保留**，宁可多一条也不丢数据；
- 项目已不存在，它名下的记录随项目一起丢弃；
- 计数器 `nextId` 取两端较大值，避免以后再撞号。

### 六、边界与已知取舍

1. **没有历史版本**：云端始终只有最新一版。误删一条记录并同步下去，云端和另一台设备就都没了，找不回来 —— 重要数据仍建议定期用「导出记录」备份。
2. **不是实时推送，且被动接收要手动触发**：本机改动靠 2.5 秒节流上行；自动补拉只在「本机有脏数据或上次失败」时发生，所以另一台设备改了之后，这台页面开着不会自己变，需要点「⟳ 立即同步」（v0.3H）或刷新网页。刻意不做常驻轮询：避免整包 JSON 反复传输，也避免拉到新版本时整页重绘打断正在填的弹层。
3. **同步码换了 = 换了柜子**，旧柜子里的数据不会自动跟过来。
4. **本地始终是主本**：`applyRemoteState()` 把云端包写回本机时直接写 `localStorage` 再重绘，刻意**不调 `save()`**，否则会反过来再触发一次同步，形成回环。

## 设计与实现要点

- **单文件**：HTML + 内联 `<style>` + 内联 `<script>`，零第三方库、零外部字体、零 CDN。除你主动开启的同步外，不发任何网络请求。
- **iOS 原生控件**：`input[type=time/date]` 在 iOS Safari 里带原生固有最小宽度，会把并排两列撑破；所有时间 / 日期输入统一 `-webkit-appearance:none` + `min-width:0`，两列容器用 `grid-template-columns:minmax(0,1fr)` 做硬约束（v0.3D 起）。
- **折叠只改 DOM 不改数据**：项目列表折叠在 `renderProjectList()` 里按可见集合渲染卡片，切换时只局部重绘项目列表（与「历史记录」折叠同一套路），不整页 `render()`、不触发 `save()`，因此同步钩子与统计口径都不受影响（v0.3E 起）。
- **搜索框放在被重绘容器之外**：项目搜索框是静态 HTML，位于 `#project-list` 之前；过滤只调 `renderProjectList()` 局部重绘，整页 `render()` 也不会重建它，因此输入焦点与已输入文字天然保留。输入走 document 上的 `input` 事件委托（与 `click` / `keydown` / `change` 一样只绑一次）。几百条项目全量 `includes` 过滤是毫秒级，不需要防抖、索引或虚拟列表（v0.3F 起）。
- **次数不落库、排序不改写数据**：热度只影响 `orderedProjectsForDisplay()` 一个比较函数（全站唯一调用点），`useCountMap()` 纯读 `state.days`；切换排序只调 `renderProjectList()` 局部重绘，不触发 `save()` / 同步钩子。组汇总、统计、时间分布、今日记录与历史记录都按完整项目列表计算，排序前后一字不差（v0.3G 起）。
- **立即同步只做手动触发**：`doSyncNow()` 直接调已有的 `runSync(true)`，不新增定时器、不改 `initSync()` 的调度条件；`runSync()` 内部本来就无条件先 `syncPull()`，且 `rev` 变化 + 本地无改动时 `applyRemoteState()` 会整包写回并重绘，所以纯接收端也能生效。刻意不引入自动轮询，流量与重绘时机都由用户一次点击决定（v0.3H 起）。
- **历史折叠只留一处状态**：`renderHistory()` 用 `RECORDS_PAGE_SIZE = 5` 与 `.records-toggle` 控制默认露出的段数；`toggleHistoryExpanded()` 只调 `renderHistory()` 局部重绘，不整页 `render()`、不触发 `save()` / 同步钩子。换日期（前后翻、日期选择器）复位展开态（v0.3I 起）。v0.3L 删掉「今日记录」卡后，另一个同类状态 `recordsExpanded` 与 `renderRecordList()` 一并移除，`historyExpanded` 成为唯一的记录分页状态；今日的明细走「点哪个小时展开哪个」的 `timelineHour`，两者互不相干。
- **换项目只挪段、不改段**：`projectOptionsHTML(opts)` 用可选参数支持默认选中与排除系统项目，`inlineNewProjectHTML()` 抽出后由编辑 / 补记两个弹窗共用；`saveRecordEdit()` 校验通过后用 `removeSegmentRaw()` + `ensureBucket()` 把同一个 seg 对象换到新 pid 的桶，不新建段、不改 `id`、不改日期，内联新建仍放在全部校验之后（失败不残留空项目）。数据结构与同步协议均未改动：单端改动由 `save()` 整包推送；两端同时改动时 `mergeRemote()` 按桶「只增不删」的既有特性仍在，属已知限制（v0.3J 起）。
- **候选列表不用浮层、局部重绘保焦点**：`.modal-panel` 带 `overflow-y:auto`，绝对定位的候选浮层会被裁，因此列表放在文档流内并限高内部滚动；`refreshProjectPicker()` 只重绘 `#picker-items`，不重建搜索框，边打字边过滤不丢焦点；搜索框 `oninput` 直接绑在弹窗内，不走主界面的全局 `input` 委托，两套搜索互不干扰（v0.3K 起）。
- **时间轴只在渲染层动**：v0.3L / v0.3M 没有改 `computeTimeline()` 的数据结构与统计口径，只在每段上多挂一个内存中的 `rec` 引用给明细行读项目名、配色与备注；也不改存储结构，所以 CSV、记录卡、历史记录、同步整包全部照旧。「一格一色」是 `renderTimeline()` 里现算的：按小时裁出各段覆盖区间 → 排序后合并去重求并集长度 → 同时记下最长段的主色 → 换算成 `opacity`（v0.3M 起）。
- **今天与历史的记录行共用一套 CSS**：小时明细行与历史行都是 `.record-row`，两者都挂 `edit-record` / `delete-record`；v0.3W 把 `openEditRecordModal()` / `openDeleteRecordModal()` 参数化为 `dayKeyOpt`，历史行按钮带 `data-day` 指明日期，因此同一套弹层能改任意一天（v0.3L 起共用，v0.3W 起历史也可编辑删除）。
- **合并先认身份、再谈字段（v0.3N）**：`mergeRemote()` 原来是「同 `id` 即同段，字段不同就新建副本」，对「同段两端各自结束」这种正常场景会误判。新增的 `mergeSameSegment()` 把身份收窄为「同 `id` **且** `start` 相同」，`end` 差异走字段合并而不是新建段；`originStart`（v0.3O）再加一层「最初起点相同即同段」的兜底。判身份与并字段分开之后，重复段这类问题在数据层就消失了，不需要在渲染层去重。
- **改起点只写一个字段（v0.3O）**：`saveAdjustStart()` 只赋 `seg.start`，其余字段逐一保持不变；`originStart` 存「最初点开始」的时刻，用来在跨端合并时认身份，所以界面上的起点可以前后挪、同步身份却不会漂。校验（今天 0 点后 / 早于现在 / 不跨天）放在写之前，失败只提示不落盘。
- **备注候选只读、不建索引（v0.3S）**：`recentNotesForProject(pid, excludeSegId)` 每次打开弹窗时遍历 `state.days` 现算，取该项目最近 3 条手写备注；不存「备注库」、不加字段、不写新 key，因此不涉及数据迁移，也不影响同步包大小。系统自动备注（`因《X》中断`）在取数时排除，避免把机器写的句子混进「我用过的话」。
- **删 DOM 必须同时补空值保护（v0.3T）**：`renderOverview()` 里有 4 处无条件写 `#stat-total` 等元素，只删 HTML 会让整页渲染直接抛错。本轮的顺序是「先给 4 处赋值加 `if (!el) return/跳过`，再删元素」，验收里专门断言全程 0 个 JS 报错。以后删任何被 JS 直接引用的节点，都按这个顺序走。
- **项目卡改版只写 CSS（v0.3U）**：71 行样式追加在 `</style>` 前，靠 grid 重排既有子元素、`::before` 画圆点、`:has(.proj-actions:empty)` 判计时中，HTML 结构与 JS 一行未动，所以排序、搜索、折叠、环形圈、⋯ 菜单、备注候选全部照旧。代价是要接受 `:has()` 的浏览器前提（iOS 15.4+ / 较新 Chromium）；不支持时只是少一个计时中高亮，布局与功能不受影响。已知窄屏现象：320px 下第二行 `.proj-today` 是单行 flex、不折行，设了每日上限的项目文字较长时会被卡片右缘裁掉一截（文档本身不横向滚动）；修法是给它加 `flex-wrap:wrap`，一行 CSS，本轮按边界未改。
- **船上穿插只加可选字段与读函数（v0.3V）**：段上多一个可选 `parent`（指向船段 id），`sanitizeSegment()` 只在真的有值时才写这个键，旧数据形状完全不变；`mergeSameSegment()` / `mergeRemote()` 保留 `parent`，跨零点拆段后由 `normalizeDayRollover()` 把 `parent` 从旧船 id 迁到新船 id，否则第二天认不回船。判断「船」用 `findBoatSegment()`（无 `parent`、非「事来则应」、且船本身不是系统项目），`findAllRunningSegments()` 一次扫出所有进行中段供状态条与卡片复用；船上段不会再被误当成船，因此不会叠出第二层。今日合计仍按原口径求和，24 格时间分布不表达重叠。
- **历史编辑 / 删除参数化 dayKey（v0.3W）**：`findSegmentById(segId, dayKey)` 只在指定那天的桶里找段，编辑 / 删除链路的可选 `dayKey` 不传时默认今天；弹层不标日期，副标题只有项目名与「可改钟点与备注，日期不变」，删除确认按 `dayKey === today` 决定「今日 / 当天总时长」。数据结构、统计口径、同步协议零改动。
- **删 DOM 要连着处理它背后的入口（v0.3X）**：编辑弹窗删掉整块项目选择器后 `onConfirm` 仍读 `#add-project`，所以不是简单删 HTML——改成把 `found.pid` 原样传回 `saveRecordEdit()`，段不换桶；`saveRecordEdit()` 里 v0.3J 的换桶分支原样保留、只是不再有入口触发。补记弹窗继续用同一套组件，函数一行未删。**v0.4D 把入口接回来了**：不复用旧的整块选择器，改成「胶囊 + 底部面板」，直接写 `modalState.pendingPid` 后由 `saveRecordEdit()` 读它，所以换桶分支重新被触发，而 `saveRecordEdit()` 本身只需要换一个 pid 来源。
- **点开始退出搜索只清纯 UI 状态（v0.3Y）**：`clearSearchQuietly()` 只做「清空输入框 + `setSearchQuery("")`」，刻意不 `focus()`（手机会弹键盘）；`setSearchQuery("")` 自带一次局部重绘，即使 `startTimer()` 提前 return 也不会留下「输入框空了但列表还在筛选」的不一致。× 与 `Esc` 仍走 `clearSearch()` 并聚焦，两条路径分工明确。
- **分类从入口改成筛选视角（v0.3Z）**：`catFilter` / `flatListOpen` / `FLAT_VISIBLE_COUNT = 3` 都是纯 UI 状态；chip 计数从 `projects` 现算，「事来则应」计入「如实知见」保证各 chip 之和 = 全部。搜索态 early-return 在分类渲染之前，匹配结果不会被 3 条折叠吞掉；进行中 / 新建高亮项目即使排在 3 条外也强制可见；原 `block()` 分组渲染整段保留不删，只换默认视图。`group` 字段继续服务目标 / 上限与 CSV 分组列，数据结构与同步协议零改动。
- **覆盖口径是纯读派生（v0.4A）**：`computeCoveredMinutes(state, dayKey, now)` 不写 `state`，只把当天所有段夹到 `[0点, 次日0点)` 后先排序再求区间并集，所以重叠只算一次、结果恒 ≤1440；未结束段在「查看今天」时算到 `now`、查看历史日期时算到当天末尾，不再把「现在」当终点（旧的 `minutesOfSegment` 就是这么算出 31 小时 59 分的）。`segmentMinutesForDay()` 只服务历史记录行，今天看今天时结果与旧函数完全一致。`computeDayStats()` 只多返回 `coveredMinutes` / `rawTotalMinutes`，`totalMinutes` 一个字节没改，因此 CSV、记录卡、同步包全部向后兼容。
- **中断只有一个入口、一个弹窗（v0.4B）**：`startTimer()` 里 v0.3V 的自动挂船分支整段删除，只有 `startBoatTask(boatPid, taskPid)` 会写 `parent`；`openInterruptSheet()` 只渲染搜索 + 候选 + 新建 + 两个按钮，「结束」走 `stopTimer(pid, "finished")`（与状态条同一个动作），遮罩 / `Esc` / 下滑走 `closeSheet()`——只移 DOM、不碰任何字段。旧的 `doInterrupt()` / `startChoreSegment()` / `clearChoreToday()` 保留为历史数据链路，新界面不再调用，所以「事来则应」不会新增但旧记录照常可读。
- **备注与时间在同一个弹窗但互不覆盖（v0.4C）**：`saveAdjustStart()` 先分别算出 `timeChanged` / `noteChanged`，都假就 `return true` 直接关闭；时间判定用 `Math.abs(startTs - seg.start) >= 60000`，因为 `type=time` 只到分钟，原始起点带秒，不设容差就会把「只补备注」误判成「调了起点」并把秒抹掉。备注走 `noteChars()` 截到 50 字，与 `sanitizeSegment()` 同一口径；只有真改了才 `save()`，避免一次开弹窗关弹窗就推一次同步。
- **改项目回到弹窗，但选与改分离（v0.4D）**：`modalState.pendingPid` 只存「打算改到哪」，胶囊渲染读它、不动数据；真正换桶仍由 `saveRecordEdit()` 用 `removeSegmentRaw()` + `ensureBucket()` 挪同一个 `seg` 对象。搜不到时 `recProjPool()` 返回空 → 渲染空态与「＋ 新建」，新建走 `createProjectForBoat()` 并记下 `modalState.newPid`；点取消时 `rollbackRecNewProject()` 把这次新建的项目删掉，避免留下 0 次记录的空项目。系统项目在 `recordProjRowHTML()` 里直接渲染成锁定胶囊，不给 `data-action`，所以点不动。
- **移动端优先**：内容最大宽度 480px，适配 `env(safe-area-inset-*)`；按钮与图标点击区不小于 44px；360px 以下自动缩小弹层字号。
- **事件委托**：只在 `document` 上绑定一次 `click` / `keydown`，通过 `data-action` 分发；`render()` 重建 DOM 不会重复绑定。
- **同源计算**：一次 `render()` 只取一次 `now`，所有合计、完成率、超额、时间轴、CSV、记录卡都从同一个 `computeDayStats()` 结果派生。
- **XSS 防护**：项目名、昵称、备注等用户输入进入 `innerHTML` 前统一经 `esc()` 转义。
- **零依赖二维码**：`QRCore` 是手写的 QR 编码器（byte 模式 / 纠错等级 L / 版本 1-9，含 Reed-Solomon 纠错与 8 种掩码惩罚评分），不引任何库。已与成熟库做过逐格位级比对，并用 OpenCV 从页面实际绘制的 canvas 里反解验证过。
- **同步不引 SDK**：直接 `fetch` 调 Supabase 的两个 RPC，不引 `supabase-js`，保持单文件与零依赖。
- **写入单一出口**：所有状态变更都经过 `save()`，同步挂钩只放在这一处，因此新增任何业务功能都自动获得同步能力。
- **键盘约定**：`Escape` 关闭菜单 / 弹窗 / 中断面板；**关闭中断面板只是关闭**，不中断、不结束、不写 `state`（v0.4B 起，原先等同「只中断」的语义已废弃）；弹窗输入框内 `Enter` 等同于点「保存」。
- **刷新行为**：重新打开一律回到页面顶部，不恢复上次滚动位置；「小时明细」展开状态（`timelineHour`）、「历史记录」展开状态、「项目列表」展开状态（`expandedGroups`）、「分类筛选」（`catFilter`）、「清单展开」（`flatListOpen`）与「项目搜索关键词」都是纯 UI 变量，不写入数据、刷新即清空（回到「全部 + 3 条」）；只有「排序模式偏好」存独立 localStorage、刷新保留但不同步。
- **自测接口**：`window.TTR` 暴露 `getState` / `setStateForTest` / `render` / `computeDayStats` / `openCardPreview` / `bjTodayKey`，v0.3V 另加 `findAllRunningSegments` / `findBoatSegment` / `normalizeDayRollover`，方便在控制台本地验证，不影响界面。
- HTML 元素上的 `data-page-node-id` 与 \`\` 是资料库托管环境留下的标记，无脚本依赖，本地直接打开无任何影响。

## 使用注意

- 不设账号；默认只存本机，清除浏览器数据 / 无痕窗口 / 换设备会导致数据不可见或丢失。要么开启跨设备同步，要么用「导出记录」备份。
- 同步是**可选**的，关掉后不影响本地记录；云端只保留一份最新快照，没有历史版本，误删后同步下去就找不回来了。
- 配对链接等同于密码，只发给你自己的设备；扫码用的浏览器就是以后记记录的那个浏览器。
- 删除项目会**连带删除该项目所有记录且无法恢复**；删除单段记录同样不可恢复。
- **全局只有一条船**：开始别的项目会结束当前段（连船上那件一起），无需二次确认；想让一件事「在船上」，只能走「中断」。
- **中断不等于结束，也不等于记录**：点「中断」只能选一件事或点「结束」；点面板外面、按 `Esc`、下滑都只是关掉弹窗，计时照旧。
- 项目名最多 10 字且不可重名；「事来则应」为保留的系统项目，不可删除、改名或设目标；v0.4B 起它只用于读旧数据，新的中断不再往里写记录。
- 备注最长 50 字，来源项目名最长 10 字。**备注只有两个写入点**：计时中点状态条「已计时」（与改起点同框），结束后点记录行 `✎`；备注框下方会出现「最近用过」的三条候选，点一下是**填入**不是替换整段逻辑，填完照样能改。
- 计时中如果发现起点点早了或点晚了，直接点状态条上的已计时数字调整；只能调到今天 0 点之后、且必须早于现在。
- 编辑 / 删除对今天与过去日期都可用（v0.3W 起，改哪天就落在哪天）；**编辑可以改钟点、备注与所属项目**（v0.4D 恢复，选完点「保存」才生效）；补记可落到今天，也可从「历史记录」补到选中的那一天；未来的时间一律拦截。
- **超过 24 小时不是 bug 了**：历史标题的「覆盖」是当天真实占用的并集（≤24 小时），小字「累计投入」才是各段相加；两者相差多少，就是这一天被几条记录同时覆盖的部分。

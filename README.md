
我的时间记录
一个单文件、零依赖、纯前端的时间记录工具：按项目记录每天的时间段，用三种口径管理投入，并把「被打断的时间」单独归到系统项目「事来则应」。手机上打开即用，数据存在本机浏览器，不需要账号、不需要服务器、不引入任何第三方库。
跨设备同步是可选项：开启后数据写入你自己的 Supabase 数据库，两台设备用一张配对二维码对齐——扫一次码即可，不用输任何口令，也不用记账号密码。

- 本地使用：双击 index.html，用 Chrome / Edge / Safari 等现代浏览器打开即可。无需安装、无需构建、无需联网。
- 在线使用：把 index.html 提交到 GitHub 仓库根目录并开启 GitHub Pages，即可通过 Pages 地址或已绑定的自定义域名（如 https://oktime.cc）访问。
  默认只存在本机浏览器：换浏览器、换设备、无痕窗口、清除浏览器数据都会导致数据不可见或丢失。两种应对——开启跨设备同步，在另一台设备扫码配对；或定期用页面底部的「导出记录」备份成 CSV。

  功能详解
  项目与计时
- 项目名最多 10 个字、不可与现有项目重名；颜色从 8 色调色板依次分配。顶部「＋」先弹三选一分组，各组标题右侧的「＋」可直接在该组新建。
- sortIndex 数值越大越靠前；新建项目排在同组首位。「事来则应」不参与排序，固定沉底。
- 卡片按钮统一显示「开始」，结束后再次开始仍显示「开始」，不再切换成「继续」；计时中的卡片不再放按钮，「中断」「结束」上浮到状态条活动卡。
- 全局最多只有一个进行中的时间段。开始另一个项目时，当前段自动标记为完成，无需二次确认：普通项目弹出 toast「《项目名》已记录 XX 分钟」；若被代关的是「事来则应」，则在状态条浮现「事来则应已记录 XX 分钟」。
- 计时中的状态条每秒只更新「已计时」数字，不会整页重绘，因此不会打断菜单、弹层或输入焦点。
  中断与「事来则应」
  点计时中状态条上的「中断」，从底部弹出面板：
- 四个快捷原因：喝咖啡休息 / 接电话 / 临时被叫走 / 事来则应，点一下回填输入框，再点一次取消选中。
- 选填「补充说明」，最多 20 字。
- 两个按钮：「中断并开始记事来则应」（实心）、「只中断」（描边）。
- 点面板外、下滑关闭、按 Escape，都等同于「只中断」，且不填备注、不弹二次确认。
- 「中断并开始记事来则应」会闭合当前段，同时立刻开始一段「事来则应」，其 sourceProject 记为被中断项目名，备注自动填「因《项目名》中断」加补充内容。

  历史记录
  用来回看和补填过去某一天。
- 日期默认是北京时间的今天；‹ › 前后翻一天，› 在今天时禁用，日期选择器不能选未来。
- 标题显示 YYYY-MM-DD 星期X，右侧一行小字「共 N 段 · 合计 H:MM」。
- 当天有记录时按从早到晚列出每段的项目、起止钟点、标签（计时中 / 中断）、备注与来源项目。
- 当天没有记录时显示「暂无记录」，并提示可点右上「＋ 记一段」补填，或换一个日期。
- 该模块的「＋ 记一段」打开的就是首页那个补记弹窗，只是目标日期取当前选中的那一天：补到哪天就记在哪天，不计入今天。
- 日期判断一律按北京时间（bjDayKeyOf / bjTodayKey），不随设备时区漂移；旧记录保留原本的日期与数量，不做任何重算。
  今日时间分布
- 24 个格子对应 0–23 点，格内按分钟比例填充项目色块，空白用斜纹表示。
- 点格子展开该小时明细（记录段 + 空白区间），再点一次收起；每个格子都有「补记一段时间」入口。
- 图例列出今天出现过的项目与「空白」。
- 下方小字采用活动区间口径：区间 = 今天第一条记录起点 → 最后一条记录终点，区间外的时段不计入；显示「活动区间 HH:MM–HH:MM · 空白 X · 最长 HH:MM–HH:MM」，没有空白时显示「没有空白」。
  每日上限、超额与统计口径
- 「适可而止」项目超过每日上限时，只做提示不自动结束计时、也不禁止开始：顶部弹一次橙色提示条，概览里「适可而止：N 个项目，M 个超额」可点开查看明细。
- 「今日合计」= 当天所有项目所有段之和，包含「事来则应」和未设目标的项目。
- 「完成 X%」只按「多多益善」组里设置了每日目标的项目计算：分子是这些项目今天已投入之和，分母是它们的目标之和。「适可而止」「如实知见」「事来则应」与未设目标的项目都不参与。超过 100% 照实显示，8px 细进度条按满格绘制。
- 「其中事来则应 XX 分钟」仅在有相关记录时显示。
- 跨天时会把进行中的段按午夜切分归属到各天；30 秒轮询只检测是否跨天，不改动任何数字。
  生成今日记录卡 / 导出记录
- 生成今日记录卡：弹窗预览一张 Canvas 绘制的 PNG（750px 宽、2 倍位图，高度随项目数增长），包含昵称、日期与星期、今日总时长、目标完成百分比、进度条、「其中事来则应 XX 分钟」，以及按三组分段列出的今日各项目小计。点「保存图片」下载为 我的时间记录-YYYY-MM-DD.png，移动端可长按图片保存到相册。
- 导出记录：把全部历史（不止今天）导出为带 UTF-8 BOM 的 CSV（防中文乱码），文件名为 我的时间记录-YYYY-MM-DD.csv。明细共 19 列：
  日期 / 项目 / 分组 / 开始 / 结束 / 时长(分钟) / 状态 / 备注 / 来源项目 / 每日目标_分钟 / 每日上限_分钟 / 当日已用_分钟 / 是否超额 / 超额_分钟 / 按日汇总_今日合计_分钟 / 按日汇总_目标合计_分钟 / 按日汇总_完成率 / 按日汇总_记录段数 / 按日汇总_超额项目数
  明细之后空一行，再追加按日汇总区：日期 / 今日合计_分钟 / 目标合计_分钟 / 完成率 / 记录段数 / 超额项目数 / 多多益善完成率。状态为「计时中 / 中断 / 完成」，进行中的段结束时间写「进行中」。导出只读数据，不改动任何记录与统计；无记录时提示「暂无记录可导出」。
  跨设备同步与配对（可选）
  默认关闭。开启后两台设备看到同一份记录，数据在你自己的 Supabase 库里；关掉同步不影响本地记录。
  第一次开启：点页面底部「跨设备同步 · 未启用」→「随机生成一个」（自动填 ok-xxxxxx-xxxx，14 位，去掉易混字符）→「启用并同步」。同步成功后配对二维码自动弹出，不用再点第二次。
  给第二台设备配对：直接扫那个码；或在已启用的设备上点同步条 →「配对一台新设备」→ 复制链接发过去。链接形如 https://oktime.cc/?pair=<同步码>。
- 打开带 ?pair= 的链接会自动填码、启用并同步，随后立刻把参数从地址栏抹掉（不留在浏览历史里，也不随外链 Referer 带出去）。
- 本机已有记录时按合并处理，云端不会覆盖本机；本机为空则直接采用云端。
- 已配对的设备再扫同一个码只提示「这台设备已经配对了」，不会把版本号重置为 0。
- 同步码至少 12 位，两台必须一字不差；码等于钥匙，谁拿到链接谁就能读到你的记录，只发给你自己的设备。
- 同步不是实时的：保存后节流 2.5 秒上行，回到前台 / 网络恢复 / 每 15 秒兜底各补一次。断网时本地照常记录，恢复后自动补传。
- 冲突按 rev 乐观锁处理：版本被别的设备抢先推进时，重新拉取、按记录 id 合并后重推一次；仍失败则提示「两台设备同时在改，请稍后再试」。删除也能同步——云端变了而本地没改动时整体采用云端。
  扫码用的那个浏览器，就是以后记记录的那个浏览器（微信扫码会落在微信的存储里，和 Safari 不共享）。建议扫码后「添加到主屏幕」，固定在同一个入口打开。

  同步的存储（可选）
  不开同步时，只有上面这一个 localStorage 键。开启后多出两处：
  位置
  内容
  localStorage["my-time-records:sync:v1"]
  同步码明文、lastRev（上次看到的云端版本号）、lastAt（上次同步时间）、enabled。只存在这台设备上
  Supabase Postgres 表 public.ttr_sync
  code_hash（同步码的 sha256，主键）/ payload（整份状态的 jsonb 快照）/ rev（版本号）/ updated_at
  云端每个同步码对应表里一行，存整份快照而不是增量日志，每次推送 rev + 1。表上没有开放任何直连策略（revoke all on table），只把两个 security definer 函数授权给匿名角色：
- ttr_pull(p_code) —— 按码哈希取回快照
- ttr_push(p_code, p_payload, p_base_rev) —— 乐观锁写入，rev 不等于 p_base_rev 时拒绝
  因此 publishable key 写在页面里是设计允许的：拿到它也只能调这两个函数，不知道码就取不到任何一行数据（直接查表返回 401）。

  设计与实现要点
- 单文件：HTML + 内联  + 内联 ，零第三方库、零外部字体、零 CDN。除你主动开启的同步外，不发任何网络请求。
- 移动端优先：内容最大宽度 480px，适配 env(safe-area-inset-*)；按钮与图标点击区不小于 44px；360px 以下自动缩小弹层字号。
- 事件委托：只在 document 上绑定一次 click / keydown，通过 data-action 分发；render() 重建 DOM 不会重复绑定。
- 同源计算：一次 render() 只取一次 now，所有合计、完成率、超额、时间轴、CSV、记录卡都从同一个 computeDayStats() 结果派生。
- XSS 防护：项目名、昵称、备注等用户输入进入 innerHTML 前统一经 esc() 转义。
- 零依赖二维码：QRCore 是手写的 QR 编码器（byte 模式 / 纠错等级 L / 版本 1-9，含 Reed-Solomon 纠错与 8 种掩码惩罚评分），不引任何库。已与成熟库做过逐格位级比对，并用 OpenCV 从页面实际绘制的 canvas 里反解验证过。
- 同步不引 SDK：直接 fetch 调 Supabase 的两个 RPC，不引 supabase-js，保持单文件与零依赖。
- 写入单一出口：所有状态变更都经过 save()，同步挂钩只放在这一处，因此新增任何业务功能都自动获得同步能力。
- 键盘约定：Escape 关闭菜单 / 弹窗 / 中断面板（等同「只中断」）；弹窗输入框内 Enter 等同于点「保存」。
- 刷新行为：重新打开一律回到页面顶部，不恢复上次滚动位置；「今日记录」展开状态是纯 UI 变量，不写入数据。
- 自测接口：window.TTR 暴露 getState / setStateForTest / render / computeDayStats / openCardPreview 等，方便在控制台本地验证，不影响界面。
- HTML 元素上的 data-page-node-id 与 `` 是资料库托管环境留下的标记，无脚本依赖，本地直接打开无任何影响。
  使用注意
- 不设账号；默认只存本机，清除浏览器数据 / 无痕窗口 / 换设备会导致数据不可见或丢失。要么开启跨设备同步，要么用「导出记录」备份。
- 同步是可选的，关掉后不影响本地记录；云端只保留一份最新快照，没有历史版本，误删后同步下去就找不回来了。
- 配对链接等同于密码，只发给你自己的设备；扫码用的浏览器就是以后记记录的那个浏览器。
- 删除项目会连带删除该项目所有记录且无法恢复；删除单段记录同样不可恢复。
- 全局只有一个进行中段，开始别的项目会自动结束当前段，无需二次确认。
- 项目名最多 10 字且不可重名；「事来则应」为保留的系统项目，不可删除、改名或设目标。
- 备注最长 50 字，中断面板「补充说明」最长 20 字，来源项目名最长 10 字。
- 编辑与补记只作用于今天的钟点，日期不变；未来的时间会被拦截。

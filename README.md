
我的时间记录
一个单文件、零依赖、纯前端的时间记录工具：按项目记录每天的时间段，用三种口径管理投入，并把「被打断的时间」单独归到系统项目「事来则应」。手机上打开即用，数据存在本机浏览器，不需要账号、不需要服务器、不引入任何第三方库。
跨设备同步是可选项：开启后数据写入你自己的 Supabase 数据库，两台设备用一张配对二维码对齐——扫一次码即可，不用输任何口令，也不用记账号密码。

- 本地使用：双击 index.html，用 Chrome / Edge / Safari 等现代浏览器打开即可。无需安装、无需构建、无需联网。
- 在线使用：把 index.html 提交到 GitHub 仓库根目录并开启 GitHub Pages，即可通过 Pages 地址或已绑定的自定义域名（如 https://oktime.cc）访问。
  默认只存在本机浏览器：换浏览器、换设备、无痕窗口、清除浏览器数据都会导致数据不可见或丢失。两种应对——开启跨设备同步，在另一台设备扫码配对；或定期用页面底部的「导出记录」备份成 CSV。

  功能详解
  项目与计时
- 项目名最多 10 个字、不可与现有项目重名；颜色从 8 色调色板依次分配。顶部「＋」先弹三选一分组；v0.3Z 起分组头不再渲染，「在组内新建」入口由顶部分组弹窗承担（等价路径，落组不变）。
- 项目顺序有两种模式（标题行「⇅」切换）：默认「按热度」按调用次数降序（v0.3G）；「按顺序」沿用 sortIndex 数值越大越靠前、新建项目排同组首位。「事来则应」不参与排序，固定沉底。
- 卡片按钮统一显示「开始」，结束后再次开始仍显示「开始」，不再切换成「继续」；计时中的卡片不再放按钮，「中断」「结束」上浮到状态条活动卡。
- 卡片长什么样（v0.3U「清单 · 呼吸」）：每张卡改两行网格。第一行是 7px 项目色圆点 + 项目名（16px）+ 细描边「开始」+ 34px 环形圈 + ⋯，第二行是 累计 N 次 · 今日合计 HH:MM · 目标 / 上限说明，用中点分隔；没有数据时第二行自动不占位。原来 4px 的左侧色条换成圆点，实心蓝胶囊换成细描边，视觉重量整体降下来，一屏能多看到一两个项目。计时中的卡片名字转靛蓝、圆点带一圈浅色光环，判定用 :has(.proj-actions:empty)，零 JS。
- 没设目标 / 上限就不画圈（v0.3Q）：goalOrbHTML() 在 targetMinutes / dailyLimit 为空时直接返回空字符串，卡片右侧不再留一个空心圆占位；设置后环形圈立刻出现。设置入口没变——⋯ →「设置每日目标 / 上限」，或新建项目后自动弹出的设置面板。
- 项目可以在三组之间移动：⋯ →「移到其它分组」→ 选目标组。移完排在目标组最前并短暂高亮。已有的每日目标 / 上限按原数值搬到新分组（目标 ↔ 上限互转，数值不变），移到「如实知见」则清空这两项；历史记录一条不动，但过去日期的完成率与超额会按新分组重新计算。「事来则应」不参与移动。
- 计时可以「在船上做」（v0.3V 方案 B）：时间是一条河，主任务像一条船。船在走的时候开始另一件事，这件事会挂到船上（段上带可选 parent 指向船段），船继续走、不自动结束；状态条给它单独一行 ● 项目名 · 船上 00:xx [收]，船卡片多出第三行 ⤷ 船上 · 项目名 … 净 xx:xx（净时长 = 船已计时 − 船上合计，不会为负）。同一条船上一次只做一件事，开新的会顶掉旧的并弹「《X》已记录 N 分钟」。点船的「结束 / 中断」会连带结束船上那件事；点船上的「收」只结束这一件、船照走。「事来则应」仍按原来的全局打断规则处理，既不当船、也不挂到船上。除此之外，没有船时开始另一个项目仍按旧规则：当前段自动标记完成、无需二次确认，普通项目弹 toast「《项目名》已记录 XX 分钟」，被代关的是「事来则应」则在状态条浮现「事来则应已记录 XX 分钟」。
- 计时中的状态条每秒只更新「已计时」数字，不会整页重绘，因此不会打断菜单、弹层或输入焦点。
- 分类作筛选、清单默认 3 条（v0.3Z）：搜索框下是一行 4 个 chip——「全部 N」「多多益善 N」「适可而止 N」「如实知见 N」，默认「全部」。点某组只显示该组项目，并在下方补一行该组当日汇总；「事来则应」计入「如实知见」，各 chip 之和 = 全部。清单是一条扁平列表（不再按组分段），默认只画 3 张卡，其余收进「⋯ 还有 N 项 · 展开全部」，展开后按钮变「⋯ 收起」。换分类会回到 3 条、不带上一组的展开态。原分组渲染函数 block() 整段保留，只是不再作为默认视图；目标 / 上限、CSV 分组列与统计口径仍按 group 字段照旧工作。
- v0.3E 的「每组 3 项」折叠在 v0.3Z 后被扁平清单取代；GROUP_VISIBLE_COUNT / expandedGroups 保留但默认视图不再走它。
- 进行中的项目强制可见：即使它排在 3 条之外，也会被提到可见区（相对顺序不变、「还有 N 项」计数相应扣减），否则会连「中断 / 结束」都点不到。新建 / 移动后的高亮项目（revealPid）同样强制可见。「按顺序」模式下新建项目（nextSortIndex() 排最前）与「移到其它分组」后排到新组首位的项目会自动进入前 3 项；「按热度」模式下这两类项目是 0 次，靠高亮期间的强制可见露出（见下）。
- 折叠与分类筛选都是纯 UI 状态：expandedGroups、catFilter、flatListOpen 只存在内存里，不写 state、不进 localStorage、不参与同步，刷新后回到「全部 + 收起 3 条」；统计、时间分布、小时明细与历史记录都按完整项目列表计算，切换前后完全一致。
- 项目搜索（v0.3F）：「我的项目」标题下方常驻一个搜索框（放大镜 + 输入框 + 清除 ×）。输入即按项目名过滤：忽略大小写、支持中文子串、空格分隔多个词需全部命中、自动忽略首尾空格；Esc 或 × 清空。项目只有 name 一个文本字段（≤10 字），没有备注 / 标签，也没有拼音或首字母搜索。
- 搜索结果跨组平铺：有关键词时忽略分类筛选与清单折叠，把所有匹配项按当前显示顺序（默认按热度、切回后按 sortIndex）列成一组，顶部显示「找到 N 项」，最多渲染 20 条并提示补充关键词；chip 在搜索时隐藏。结果复用完整项目卡，直接点「开始」即可计时，右侧 ⋯ 菜单、目标环、今日合计都在。
- 点开始就退出搜索（v0.3Y）：搜索结果里点「开始」后输入框静默清空、has-value 移除、× 隐藏、「找到 N 项」消失，回到默认视图。用的是 clearSearchQuietly()，不抢焦点（手机上不会弹键盘），也不写 state / 不触发同步。手点 × 或按 Esc 仍走 clearSearch() 并聚焦输入框，可以接着搜下一个。
- 清空关键词立刻回到「分类筛选 + 3 条清单」视图，此前选过的分类与展开态原样保留（catFilter / flatListOpen 不受影响）。没有匹配时给「没有找到「…」」提示，关键词经 esc() 转义，不会注入 HTML。
- 搜索是纯 UI 状态：searchQuery 只存内存，不写 state、不进 localStorage、不参与同步，刷新即清空；过滤只局部重绘项目列表，不触发 save() / 同步钩子。统计、时间分布、小时明细与历史记录始终按完整项目列表计算，搜索前后完全一致。
- 按调用次数排序（v0.3G）：默认「⇅ 按热度」，三组内各自按调用次数降序；次数相同回退 sortIndex 降序（新建 / 移动后的 0 次项目仍是「0 次区」第一，不会沉到末尾），再相同回退原始下标保证稳定。系统项目「事来则应」不参与排序、始终沉底，也不显示次数。因而折叠露出的前 3 项就是该组调用最多的 3 项。
- 次数口径：从记录段现算，不存计数器。useCountMap() 遍历 state.days 所有天，统计每个项目名下的时间段条数（含今天、含补记与中断代记；跨零点拆段会算两次，属可接受的罕见情况）。好处是上线即刻按历史记录排出热度、老数据零迁移、删记录次数自动减；更关键的是同步合并按段 id 去重、两端独有的段都保留，所以次数天然是两端之和，不会出现两台手机各自点了几次、同步后少算的情况。
- 标题行「⇅ 按热度」/「⇅ 按顺序」显示当前模式，点击切换；偏好存独立 localStorage 键 my-time-records:sort-mode:v1，不进 state、不参与同步、刷新保留，各设备可有自己的偏好。两种模式下卡片右侧都显示「累计 N 次」淡灰小字（放在 .proj-today 列内，不占水平宽度，避免窄屏挤压项目名）。
- 新建 / 移动后仍看得见：高亮期间的项目（revealPid）与进行中项目一样强制放进折叠可见区，否则热度排序下 0 次项目会沉进「还有 N 项」、applyReveal() 找不到卡片，浅蓝高亮与自动滚动都会失效。新建后紧接的「设置目标」面板会盖住高亮（1.3 秒即过期），关掉面板时重新高亮一次；若新建时还停在搜索视图，会先静默清空搜索词再高亮。
  中断与「事来则应」
  点计时中状态条上的「中断」，从底部弹出面板：
- 四个快捷原因：喝咖啡休息 / 接电话 / 临时被叫走 / 事来则应，点一下回填输入框，再点一次取消选中。
- 选填「补充说明」，最多 20 字。
- 两个按钮：「中断并开始记事来则应」（实心）、「只中断」（描边）。
- 点面板外、下滑关闭、按 Escape，都等同于「只中断」，且不填备注、不弹二次确认。
- 「中断并开始记事来则应」会闭合当前段，同时立刻开始一段「事来则应」，其 sourceProject 记为被中断项目名，备注自动填「因《项目名》中断」加补充内容。

  编辑弹窗不再改所属项目（v0.3X 方案 A）：v0.3J / v0.3K 加进来的整块「项目（可改到别的项目）」——标签、搜索框、已选条、候选清单、「＋ 直接新建项目」——已按「平时很少用到」的判断整块删除。现在编辑只做两件事：改钟点、改备注，副标题统一为「项目名 · 可改钟点与备注，日期不变」。保存时把原项目 id 原样传回，saveRecordEdit() 里 v0.3J 的换桶逻辑仍保留但不再被触发，段不换桶、日期不变，弹窗高度从约 752px 降到约 397px。补记弹窗不受影响，仍保留完整的可搜索项目选择器与「＋ 直接新建项目」。
  历史记录也能编辑 / 删除（v0.3W）：历史记录不再是只读视图，每行与今日小时明细同款，带 ✎ 编辑 / × 删除（进行中的段只给 ×）。按钮带 data-day，openEditRecordModal / openDeleteRecordModal / saveRecordEdit / deleteRecordById 都接受可选的 dayKey，不传时默认今天；弹层副标题不标日期；删除确认按日期区分「今日总时长」/「当天总时长」。改哪天就落在哪天的桶里，今天与统计口径互不干扰。
  弹窗内项目选择改为搜索（v0.3K）：补记与编辑两个弹窗的「事项（项目）」由原生 <select></select> 换成可搜索选择器——搜索框 +「已选」条 + 限高候选列表；输入项目名即过滤（复用主界面同款口径：空格分词 AND、忽略大小写、最多 20 条），点一行即选中，组别以小标签显示而不再用 optgroup 大标题。补记弹窗默认空白不预选，未选时保存会提示「请选择要补记的项目」；编辑弹窗仍预选当前段归属且排除系统项目。选中 pid 仍存 #add-project（改为 hidden 字段），两个保存函数、超额提示与内联新建链路零改动；搜索词只存在于弹窗 DOM，关闭即消失，不写 state / localStorage、不触发 save() / 同步。搜索框按 Enter 只选中第一个候选，不会误触保存。（v0.3X 起编辑弹窗不再使用项目选择器，本节描述现在只适用于补记弹窗。）
  备注框可以直接点最近三条（v0.3S）：补记与编辑两个弹窗的备注框下方会多出「最近用过 · 项目名」和最多 3 枚浅蓝胶囊。点一下就把那句备注填进输入框、光标落在句尾，仍然可以继续改、清空或整句重打；手动打字后高亮消失。候选完全从已有记录里现算（recentNotesForProject() 只读 state.days），不新增存储字段、不改数据结构、不写新的 localStorage 键，所以别的设备同步过来的备注也会自然出现在候选里。取数口径：按当前项目、同句去重、排除正在编辑的这一段、排除系统自动生成的「因《X》中断」、按记录段的开始时间倒序；一句都没写过就整块不显示（不留空标签）。换项目时候选立刻刷新；补记弹窗默认不预选项目，所以先选事项才出现候选，编辑弹窗打开即可见。
  计时中可以直接改开始时间（v0.3O）：点状态条上的已计时数字，弹出「调整开始时间」——显示当前起点与已计时，可以改钟点，也可以按 −15 分钟 / −30 分钟 / −1 小时 快捷回拨，改的时候下面实时预览新的起点与已计时。保存只改 start 一个字段，id、所属项目、备注、endType=running、end=null 全都不动，所以计时不会被中断、也不会多出一段。校验三条：必须在今天 0 点之后、早于现在、不跨天；调过的段会带一个「起点已调整」小标记。跨设备同步也做了兼容：新段在开始时写入 originStart（最初点「开始」的时刻），旧段第一次被调整时补写，合并时靠它认出「两端说的是同一段」。
  编辑与补记写入后，概览里的小时明细、时间轴色块、CSV、记录卡、历史记录全部从同一份状态实时重算，不需要任何手动同步。备注直接跟在「N 分钟」后面显示：今日小时明细一行空间窄，超长由 CSS 省略（.tl-note 限宽 38%），不再折叠成「点开看全文」（v0.3L 起）；历史记录一行更宽，备注完整换行显示。
  历史记录
  用来回看和补填过去某一天。
- 日期默认是北京时间的今天；‹ › 前后翻一天，› 在今天时禁用，日期选择器不能选未来。
- 标题显示 YYYY-MM-DD 星期X，右侧一行小字「共 N 段 · 合计 H:MM」。
- 当天有记录时按从早到晚列出每段的项目、起止钟点、标签（计时中 / 中断）、备注与来源项目。
- 默认只显示前 5 条（v0.3I）：与概览的小时明细共用同一套记录行样式与分页口径，段数超过 5 条时底部出现「展开全部（共 N 条）」，点开看全天、按钮变「收起」；≤ 5 段或空日期不出现按钮。默认露出当天最早的 5 段，展开后仍是从早到晚。切换日期（前后翻 / 日期选择器）会自动收回；展开状态只存内存、刷新即复位。
- 可逐条编辑 / 删除（v0.3W）：历史行不再是只读，与今日小时明细同款带 ✎ 编辑 / × 删除；改钟点与备注、删段都直接作用于当前查看的那一天（按钮带 data-day），弹层不标日期，删除确认写「当天总时长」。进行中的段只给 ×，仍须先结束才能编辑。
- 当天没有记录时显示「暂无记录」，并提示可点右上「＋ 记一段」补填，或换一个日期。
- 该模块的「＋ 记一段」打开的就是首页那个补记弹窗，只是目标日期取当前选中的那一天：补到哪天就记在哪天，不计入今天。
- 日期判断一律按北京时间（bjDayKeyOf / bjTodayKey），不随设备时区漂移；旧记录保留原本的日期与数量，不做任何重算。
  今日时间分布（v0.3M 方案 B，v0.3T 起无独立标题）
  24 格仍然是 1 小时一格、可点，视觉层在 v0.3M 做了精简：一格一色，不再往格子里叠多段比例色块和空白斜纹。v0.3T 起这一块不再有自己的标题——「今日概览」标题行右侧只有一行小字「每格1小时·点开看明细」，点开某格后它变成「再点一次收起」。
- 概览卡只剩这一块（v0.3T）：今日累计大数字、目标、完成百分比、细进度条与「适可而止」超额汇总整块已删，卡片高度从约 383px 压到约 167px，首屏能多露 1–2 个项目。
- 一格一色：取这一小时里占时最长那一段的项目色。重叠的段先按区间合并去重，再算覆盖率，不会重复累加。
- 深浅 = 这一小时的投入：按该小时记录区间的并集长度 / 60 换算成 opacity 0.28–1，满一小时为 1。没记录的格子保持底色 #EDF1F7，不填色。
- 无边框细格：24 格是无缝排列的圆角细格（3px 间隙、5px 圆角、28px 高），颜色本身就是分隔，不再画边框。
- 刻度在色带下方：0 / 6 / 12 / 18 / 23 移到格子下方并降一档灰度，让色带本身更安静。
- 图例压成一行：■ 有记录　□ 空白　深浅 = 这一小时的投入，不再逐项列出十几种项目色。项目名与颜色在点开的明细里逐行给出，信息没有丢。
- 点格子展开该小时明细：上方是记录段（项目名、真实起止、整段分钟、计时中 / 中断标签、来源项目、备注），下方是落在这一小时里的空白区间；再点一次收起。明细里可用 ✎ 编辑、× 删除，底部「＋ 补记一段时间」直接补记这一小时。计时中的段只给 ×（要先结束才能编辑）。
- 跨小时的段会在它横跨的两个格子里各出现一次，但两处都指向同一段（显示的是真实起止与整段分钟，与编辑弹窗一致），不是被拆成了两段。
- 单小时互斥：同时只展开一个小时，点另一个会自动收起前一个。timelineHour 只是内存里的 UI 状态，不写 state、不进 localStorage、不参与同步，刷新即回到全部收起。
- 空白小字采用活动区间口径：区间 = 今天第一条记录起点 → 最后一条记录终点，区间外的时段不计入；显示「活动区间 HH:MM–HH:MM · 空白 X · 最长 HH:MM–HH:MM」，没有空白时显示「没有空白」。
